# Learning structure editor

Implemented in v0.2.24. Open **Course → Aufbereitung → Struktur bearbeiten**.

The editor keeps the observed Moodle hierarchy separate from a user-owned learning structure. It edits one level at a time, with separate **Skript** and **Aufgaben** lists. Task groups link to one or more script units rather than becoming their child chapters. Name-based starting suggestions are not confirmed source-use decisions.

## Editing

Drag the visible handle to reorder siblings. Pointer, touch and keyboard sensors are enabled; keyboard users pick up/drop with Space and cancel with Escape. Editing a name does not initiate dragging. Children retain their parent and move with the logical unit. Open a parent's child list to sort that level.

The row's options contain the original name, parent selection, task-to-script links and movement between the script and task areas. Long labels in selection lists are searchable and single-line, with the full text in their title. Course tabs scroll horizontally instead of wrapping.

**Ausblenden** sets reversible visibility; **Ausgeblendete** shows hidden rows and **Wieder einblenden** restores them. Nothing is hard-deleted. Parent visibility also affects descendants. Source occurrences, source-use decisions, historical learning versions and learner answers remain intact. Hidden units are not selected for a new generation run. Existing active course content is not regenerated by saving the structure.

## Persistence and compatibility

`PipelineUnit` keeps its existing `id`, `title`, `parentId` and `order`, with optional fields:

| Field | Meaning |
| --- | --- |
| `kind` | `script` or `tasks`; legacy units default to `script`. |
| `hidden` | Reversible visibility flag; defaults to false. |
| `customTitle` | Local display-name override; null restores the original title. |
| `sourceGroupId` | Link to the observed Moodle group, where applicable. |
| `scriptUnitIds` | Script units associated with a task group. |

Observed Moodle names and source identities are never written back to Moodle. Display names use `customTitle ?? title`. Original group names remain inspectable and refreshed separately from aliases. Existing renamed units are conservatively interpreted as aliases when their source identity is known.

The existing revision-checked structure endpoint persists edits. Omitted previously stored units become hidden rather than being destroyed. Invalid cross-area parent relationships, cycles and invalid task-to-script links are rejected. Save conflicts preserve the local draft for reconciliation.

These fields are accepted by the application API. The opt-in MCP structure tool still advertises the older structure schema; its schema extension is not included in this release. MCP write permissions remain unchanged.

## Validation

Backend regressions cover separate hierarchy types, original-name preservation, aliases, reversible hiding, retained source decisions and learner state, and revision conflicts. Frontend regressions cover sibling drag ordering, unchanged descendants, label reset, hidden-parent visibility and task movement. Browser QA uses the isolated synthetic workflow fixture, including real mouse and touch drag interactions. Production checks are read-only.
